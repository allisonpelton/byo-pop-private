# Big Money Deluxe port

Big Money Deluxe (PopCap Games, 2005) is the second game in this repository. It is decompiled and
ported the same way as Bejeweled Deluxe: the original's game classes are translated function by
function onto the portable SexyAppFramework (`framework/`, SDL2 + Emscripten), and the game
data is copied from the user's own install. Nothing from the game itself is in the repository.

## The binary

- The Steam install (`steamapps/common/Big Money Deluxe`) has two executables. `WinBM.exe` is PopCap's
  2006 DRM wrapper (VC7.1, Flash trial UI) with the unencrypted game PE appended after the
  `!popcapdrmprotect!` marker: 1,245,184 bytes at file offset 0x531a2.
- `BigMoney.exe` is iWin's AutoWrap build of the same 2005-11-14 link, behind an Armadillo-style
  protector. It is not used.
- The game PE was linked 2005-11-14 with Visual Studio .NET 2002 (MSVC 7.0, no LTCG). It has full RTTI
  (139 classes, 159 vtables). The game code is 0x401000-0x421830: 334 functions and about 130 KB,
  in 17 source files linked in alphabetical order.
- The framework is SexyAppFramework 1.2 (see FRAMEWORK_12.md); the libraries are ImageLib (libpng,
  libjpeg, zlib), BASS 2.0 for music and DirectSound for sounds.

## Reproducing the analysis

Ghidra 12.1.4 + JDK 21 (`E:\retools`), Python 3, and a public SexyAppFramework 1.2 tree for the slot
and field names ([sandboxmo-de/SexyAppFramework-v1.2](https://github.com/sandboxmo-de/SexyAppFramework-v1.2),
reference only, not part of this repository).

```bash
python tools/extract_game_exe.py "A:/SteamLibrary/steamapps/common/Big Money Deluxe/WinBM.exe" -o re/bigmoney/bin/BigMoneyGame.exe
python tools/rtti_msvc70.py re/bigmoney/bin/BigMoneyGame.exe re/bigmoney/rtti
MSVC70=1 SYMBOLS=re/bigmoney/rtti.jsonl build/native/rundesk.exe bash tools/ghidra_import.sh re/bigmoney/bin/BigMoneyGame.exe bigmoney_game re/bigmoney/ghidra
python tools/rtti_msvc70.py re/bigmoney/bin/BigMoneyGame.exe re/bigmoney/rtti --functions re/bigmoney/ghidra/functions.jsonl
GHIDRA_PROJECT=bigmoney_game GHIDRA_PROGRAM=BigMoneyGame.exe EXPORT_DIR="$PWD/re/bigmoney/ghidra" build/native/rundesk.exe bash tools/ghidra_headless.sh apply games/bigmoney/docs/symbols/*.jsonl
python games/bigmoney/tools/bigmoney_inventory.py
```

`re/` is git-ignored: the carved exe and Ghidra's export contain the game's code and strings.

- **MSVC 7.0 workarounds** (survey groundwork G4). Ghidra's RTTI analyzer rejects MSVC 7.0's 24-byte
  base class descriptors and recovers no classes, so `tools/rtti_msvc70.py` reads the RTTI itself and
  writes `Class::vfNN`, `vftable_*` and `Class::ctor_or_dtor_*` names.
- `MSVC70=1` makes `ghidra_import.sh` run `DisableNoReturnDiscovery.java` as a pre-script (the
  "Non-Returning Functions - Discovered" analyzer marks `_free` noreturn and truncates callers) and
  skip `RecoverClassesFromRTTIScript`.
- The scripts are in the worktree's own `tools/ghidra_scripts`, so Ghidra compiles them into a fresh
  OSGi bundle with JDK 21. The stale JDK 23 bundles from earlier GUI runs are never used.
- **Framework names**. `tools/saf_vtable_layout.py` computes MSVC vtable layouts from the 1.2 headers
  (overloads grouped and reversed, as MSVC does). It names every framework slot and checks each class's
  slot count against the binary.
- `tools/saf_struct_layout.py` computes the field offsets, checked against anchors in the disassembly.

## Building and running

```bash
python games/bigmoney/tools/stage_bigmoney_assets.py   # copies images/data/sounds/music/properties to assets/bigmoney/
tools/build.sh native                          # build/native/bigmoney.exe (and Bejeweled)
tools/build.sh web                             # build/web/bigmoney.html/.js/.wasm
```

- **Native.** `bigmoney.exe` finds `assets/bigmoney/` next to itself (or up to two levels up), or the
  Steam install. `-gamedir=` overrides that.
- Saves go to `%APPDATA%\wasm-bejeweled\Big Money Deluxe\`: `savegame.dat`, `hiscores.dat`, and
  `registry.ini` for the original's `HKCU\Software\PopCap\BigMoney` values.
- **Web.** `bigmoney.html` imports the player's game folder (or a .zip of it) into its own
  IndexedDB-backed folder `/bmpersist`, separate from Bejeweled's `/persist`. It saves the same way as
  Bejeweled's shell: IDBFS syncs, a localStorage backup of the user files, and one running copy per
  browser.
- Test runs follow `CLAUDE.md`: native runs only under `build/native/rundesk.exe`, and web pages only with
  `?silent=1`.
- `games/bigmoney/tools/run_script.sh <script> <user dir> [seconds] [-seed=N ...]` runs a `-script`
  file that way, with `-fast` and a time limit. Afterwards it stops only this checkout's
  `bigmoney.exe`, if one was left over.
- The same seed and script give identical screenshots on every run. The game's random numbers are the
  board's MT19937 and an exact copy of MSVC `rand()`, both seeded from `-seed`.

## Status (2026-10-18)

- **Analysis**: complete. GAME_NOTES.md has the overview plus five parts; every game function is in the
  inventory and named in Ghidra.
- **Native port**:
  - every game class is translated (`games/bigmoney/src`, about 9,600 lines);
  - it builds without warnings;
  - checked in scripted runs under rundesk:
    - the title, selector and help screens;
    - Action, Strategy and Puzzle;
    - level-up with the stats panel, game over and the high-score screen;
    - name entry (`hiscores.dat` byte-identical in format), play again and the Options dialog;
    - quit and continue (`savegame.dat`);
  - the same seed and script give the same screenshots on every run.
- **Web build**: `bigmoney.html`, checked in the Browser pane with `?silent=1`:
  - importing the game folder (as a .zip) into `/bmpersist`;
  - the title, selector and help screens, and play;
  - a reload in the middle of a game: the localStorage backup brings the save back, and "Continue?"
    restores it;
  - no console errors.
- **Not yet compared with the original**: the original exe is not run (BASS sound, DRM), so frame-level
  fidelity rests on the analysis. Part 1 section 11 and the open-question lists say where it is
  uncertain.
