# Big Money Deluxe port

Big Money Deluxe (PopCap Games, 2005) is the second game in this repository. It is decompiled and
ported the same way as Bejeweled Deluxe: the original's game classes are translated function by
function onto the portable SexyAppFramework (`framework/`, SDL2 + Emscripten), and the game
data is copied from the user's own install. Nothing from the game itself is in the repository.

## The binary

- The Steam install (`steamapps/common/Big Money Deluxe`) has two executables. `WinBM.exe` is PopCap's
  2006 DRM wrapper (VC7.1, Flash trial UI) with the unencrypted game PE appended after the
  `!popcapdrmprotect!` marker: 1,245,184 bytes at file offset 0x531a2.
- `BigMoney.exe` is iWin's AutoWrap build of the same 2005-11-14 link, behind an Armadillo-style
  protector. It is not used.
- The game PE was linked 2005-11-14 with Visual Studio .NET 2002 (MSVC 7.0, no LTCG). It has full RTTI
  (139 classes, 159 vtables). The game code is 0x401000-0x421830: 334 functions and about 130 KB,
  in 17 source files linked in alphabetical order.
- The framework is SexyAppFramework 1.2 (see FRAMEWORK_12.md); the libraries are ImageLib (libpng,
  libjpeg, zlib), BASS 2.0 for music and DirectSound for sounds.

## Reproducing the analysis

Ghidra 12.1.4 + JDK 21 (`E:\retools`), Python 3, and a public SexyAppFramework 1.2 tree for the slot
and field names ([sandboxmo-de/SexyAppFramework-v1.2](https://github.com/sandboxmo-de/SexyAppFramework-v1.2),
reference only, not part of this repository).

```bash
python tools/extract_game_exe.py "A:/SteamLibrary/steamapps/common/Big Money Deluxe/WinBM.exe" -o re/bigmoney/bin/BigMoneyGame.exe
python tools/rtti_msvc70.py re/bigmoney/bin/BigMoneyGame.exe re/bigmoney/rtti
MSVC70=1 SYMBOLS=re/bigmoney/rtti.jsonl build/native/rundesk.exe bash tools/ghidra_import.sh re/bigmoney/bin/BigMoneyGame.exe bigmoney_game re/bigmoney/ghidra
python tools/rtti_msvc70.py re/bigmoney/bin/BigMoneyGame.exe re/bigmoney/rtti --functions re/bigmoney/ghidra/functions.jsonl
GHIDRA_PROJECT=bigmoney_game GHIDRA_PROGRAM=BigMoneyGame.exe EXPORT_DIR="$PWD/re/bigmoney/ghidra" build/native/rundesk.exe bash tools/ghidra_headless.sh apply games/bigmoney/docs/symbols/*.jsonl
python games/bigmoney/tools/bigmoney_inventory.py
```

`re/` is git-ignored: the carved exe and Ghidra's export contain the game's code and strings.

- **MSVC 7.0 workarounds** (survey groundwork G4). Ghidra's RTTI analyzer rejects MSVC 7.0's 24-byte
  base class descriptors and recovers no classes, so `tools/rtti_msvc70.py` reads the RTTI itself and
  writes `Class::vfNN`, `vftable_*` and `Class::ctor_or_dtor_*` names.
- `MSVC70=1` makes `ghidra_import.sh` run `DisableNoReturnDiscovery.java` as a pre-script (the
  "Non-Returning Functions - Discovered" analyzer marks `_free` noreturn and truncates callers) and
  skip `RecoverClassesFromRTTIScript`.
- The scripts are in the worktree's own `tools/ghidra_scripts`, so Ghidra compiles them into a fresh
  OSGi bundle with JDK 21. The stale JDK 23 bundles from earlier GUI runs are never used.
- **Framework names**. `tools/saf_vtable_layout.py` computes MSVC vtable layouts from the 1.2 headers
  (overloads grouped and reversed, as MSVC does). It names every framework slot and checks each class's
  slot count against the binary.
- `tools/saf_struct_layout.py` computes the field offsets, checked against anchors in the disassembly.

## Building and running

```bash
python games/bigmoney/tools/stage_bigmoney_assets.py   # copies images/data/sounds/music/properties to assets/bigmoney/
tools/build.sh native                          # build/native/bigmoney.exe (and Bejeweled)
tools/build.sh web                             # build/web/bigmoney.html/.js/.wasm
```

- **Native.** `bigmoney.exe` finds `assets/bigmoney/` next to itself (or up to two levels up), or the
  Steam install. `-gamedir=` overrides that.
- Saves go to `%APPDATA%\wasm-bejeweled\Big Money Deluxe\`: `savegame.dat`, `hiscores.dat`, and
  `registry.ini` for the original's `HKCU\Software\PopCap\BigMoney` values.
- **Web.** `bigmoney.html` imports the player's game folder (or a .zip of it) into its own
  IndexedDB-backed folder `/bmpersist`, separate from Bejeweled's `/persist`. It saves the same way as
  Bejeweled's shell: IDBFS syncs, a localStorage backup of the user files, and one running copy per
  browser.
- Test runs follow `CLAUDE.md`: native runs only under `build/native/rundesk.exe`, and web pages only with
  `?silent=1`.
- `games/bigmoney/tools/run_script.sh <script> <user dir> [seconds] [-seed=N ...]` runs a `-script`
  file that way, with `-fast` and a time limit. Afterwards it stops only this checkout's
  `bigmoney.exe`, if one was left over.
- The same seed and script give identical screenshots on every run. The game's random numbers are the
  board's MT19937 and an exact copy of MSVC `rand()`, both seeded from `-seed`.
- `-autoplay=<seed>` (with `-autoplaymode=0..2`, `-autoplayskill=1..3`, `-autoplaygames=N`,
  `-autoplaycap=N`, `-autoplaylog=<file>`, `-autoplayshot=<prefix>`): a bot with its own RNG plays whole
  games through script input (`games/bigmoney/src/testhooks/Autoplay.h`). It goes through the title,
  selector and help screens, plays groups, clicks "next level", enters a name for a high score and
  plays again. `-autoplaylog` writes its input as a replayable `-script` file.

## Mods

Big Money uses the shared mod system (`platform/ModManager.h`).
- **Installing a mod (native).** Copy the mod's folder into `build/native/mods-bigmoney/`, or pass
  `-modsdir=`.
- **Installing a mod (web).** Use the page's Mods dialog.
- **What a mod can change.** These are checked for Big Money:
  - image replacements, including HD art (`images/<name>@2x.png` or `@4x`);
  - `imagePatches` that replace part of a sheet;
  - sound remaps (`files`);
  - texts: inline `strings`, or properties files that can also replace the 27 rank titles (`gRankNames`).
- **HD art through the game's own pixel edits.** Five places edit pixels directly:
  - the highlighted coins;
  - the grey selector pictures;
  - the "Deluxe" badge's flash;
  - the level-up squash;
  - the stats panel's fade.

  `src/HDPixels.h` repeats each edit on the HD pixels, so HD art stays sharp there too.
- **Sign that mods are on.** With any mod enabled, the "$" of the score display gets a double stroke
  (`src/ModIndicators.h`). It uses no random numbers, so a modded game plays out exactly like an
  unmodded one.
- **Music.** The music is one module, `music/QualityTime_BigMoney.it`, whose songs start at set order
  positions. A mod can replace the whole module with one that has the same layout. Replacing a single
  song would need the shared mixer to remap per order position (not yet).
- **The mod menu** (shared; `docs/MOD_MENU.md`). It turns mods on and off, orders them, and edits the
  settings mods declare.
  - **Opening it.** Press F2 on any screen. Options also gets a MODS button, in the original's unused
    Register slot, shown while an installed mod has settings.
  - **When values apply.** In Big Money every value applies at a restart.
  - **Restart game.** While a game can be saved, it asks first and says where that game goes. It is
    refused while a high-score name is being entered. A restart keeps `-replaydir` and a `-gameseed`
    still waiting for its game (`WinBMApp::HasGameInProgress`, `CanRestartNow`, `GetRestartArgs`).
  - **Settings.** Setting values reach the tunables, features and sign checks through each mod's
    effective manifest.
- **Gameplay settings.** A mod.json `"tunables"` object can change:
  - minting speed (Action) and rows per click (Strategy);
  - the money meter's size and drain;
  - the number of coin colours;
  - the smallest clickable group;
  - bags per level;
  - the score multiplier and the points for each group size;
  - how many levels ahead Normal and Hard start.

  `src/ModRules.h` lists every key with the original's value and its allowed range. A mod with tunables
  keeps its own high-score tables and save (`hiscores-<key>.dat`, `savegame-<key>.dat`), so its scores
  never mix with the normal game's. Without tunables the game plays exactly as before: the screenshot
  regression and autoplay input logs in all three modes are unchanged.
- **Set seed.** `-gameseed=N` (native) or `?seed=N` (web), with N from 1 to 4294967295. Every new game
  gets the seed until one is played on it (its first valid click or its game over).
  - In a seeded game, every random choice that shapes the board comes from the seed's own generator:
    new coins, bag columns, puzzles and dollar bombs. Effects draw from a second generator.
  - So the first level always starts the same, and in Strategy and Puzzle the same clicks give the same
    game. Action mints in real time, so there it depends on timing as well.
  - Seeded games keep their own high-score tables (`hiscores-seeded.dat`).
  - The stats panel at each level end and at game over shows "SEED n". Unseeded games show nothing
    there, as the original.
  - A seeded save ends in an 8-byte trailer, which the original's reader ignores, so the game stays
    seeded when resumed. Unseeded saves are unchanged.
- **Replays** (the `replays` mod, `features.replays`; `src/Replay.h`).
  - **Recording.** Every game played from its start is recorded and kept when it reaches its game-over
    screen, as `<date>-<mode>-<skill>-<score>.bmr`. Native replays go to `<user dir>/replays`
    (`-replaydir=`); web replays go to `/bmpersist/replays`.
  - **What is kept.** The newest 50 (`keep`), plus every replay whose score made a local table
    (`-keep` in its name). Abandoned and resumed games are not kept.
  - **Watching.** Press R on the game-over screen to watch the game just played. Native builds also take
    `-replay=<file>`, and the web page has a Replays panel to watch, download, delete or import replays.
    While watching: 1 to 4 for 1x to 8x, space to pause, Esc or New Game to stop.
  - **Limits.** A watch never saves, counts a game or enters a high score. It needs the same gameplay
    mods as the recording.
  - **How it works.** A replay holds the board's seed, the player's clicks, hover moves and next-level
    presses at their board ticks, and the bag-column draws. The board is deterministic from those, so a
    watch plays the same game, and checks it at the end ("replay: verified" in the log: same end tick,
    score, level and coins).
  - **Tested.** Replays of all three modes, seeded and with tunables, verify at 1x and 8x, including
    natively recorded replays watched in the web build.
  - **Inspecting files.** `tools/bmr.py` prints a replay's contents.
- **LiveSplit** (the `livesplit` mod, `features.livesplit`; Windows builds; `src/LiveSplitObserver.h`).
  - **The block.** After every update the game fills a tagged, read-only block in its `.data`
    (`src/LiveSplitBlock.h`). It uses the same magic and protocol as the Bejeweled port's, with game id
    "BMDX".
  - **The script.** `tools/livesplit/BigMoneyDeluxe-byopop.asl` reads the block. It starts LiveSplit's
    timer at the first level's "Go!" (never for a resumed save or a replay), splits when a level is
    complete or the score on screen reaches a segment's number, and resets when the run's game ends.
  - **Categories.** Big Money has no speedrun.com board, so the categories are suggestions. A category
    name with a mode and skill in it ("Strategy Easy - 5 Levels") starts only on that mode and skill.
  - **The mod.** It changes nothing in play (the screenshot regression is byte-identical with it on). On
    first use it copies its split templates to `<user dir>/livesplit`.
  - **Tests.** `tools/livesplit/run_tests.sh` (under rundesk) plays bot and scripted games, then checks:
    - `check_asl_offsets.py`: the script's field table and magic match the game's;
    - `asltest`: the script compiles as LiveSplit compiles it (C# 5);
    - `lsprobe.py --check`: a 64-bit process reading the live game finds the block and only ever sees
      snapshots the game wrote;
    - `lsdecide.py`: 24 scenarios (levels, scores, mode and skill guards, New Game, quitting, resumed
      games, replays, the mod off). Each one's events match the expected ones and the real script's
      decisions, through `asltest`.
  - **Not done.** A manual test with LiveSplit itself would need it downloaded first (the user's call).
- **Puzzle solver** (the `puzzle-solver` mod, `features.puzzleSolver`; `src/PuzzleSolver.h`). Puzzle
  mode only.
  - **What it works out.** Whether some clicks still drop the bags the level needs. It looks again
    whenever the board stops moving. A line above the coins shows what it found: thinking, "can still be
    won", "can no longer be won" (in red), or "too many ways to tell" when it reaches its limit first.
  - **Hints.** H, or a click on that line, makes the next group of a winning line blink. A hint costs a
    share of the score (10% by default, rounded up), a fixed amount, or nothing. The first hints of each
    level are free (one by default). A hint is refused when the score can't pay, and there is one hint
    per board position.
  - **Undo.** U, or a click on the undo line, takes back the last click: coins, bags, score and streaks
    go back to just before it.
    - **Price.** A fixed amount (250 by default), a share of the score it goes back to, or nothing.
      Hints and undos bought since that click stay paid. Each level has three undos by default.
    - **How.** Each click first keeps a snapshot: the savegame's bytes, plus what the savegame leaves
      out (the colour and combo streaks, the whole random generator). An undo reads that snapshot back,
      so the game goes on exactly as if the click had never been made. A level keeps as many snapshots
      as it has undos, and a new level starts with none.
    - **Limits.** There is no undo after the game is over, so with "End the game when lost" on, a losing
      click can't be taken back.
  - **Warnings.** "Losing clicks" can be set to "Show in red": the group under the mouse turns dark red,
    and the status line says so, when clicking it would leave a level that no clicks can win. "Show and
    refuse" also refuses that click, as long as the solver has a winning one.
    - **How.** A second search checks the hovered group once the board is still and the solver has its
      answer, with the same budget per tick. A group "loses" only when no way the bags can land is
      winnable.
    - **Limits.** The answer for a group stays until the board changes. There are no warnings in a level
      that is already lost.
  - **Ending the game.** With "End the game when lost" on, the game is over as soon as no clicks can win
    the level, instead of when no group is left.
  - **Settings** (mod menu, F2; all apply at a restart):
    - what to show (always, only when lost, never), and ending the game when lost;
    - hints on or off, their price and the free ones;
    - undo on or off, its price and how many per level;
    - losing clicks: not checked, shown in red, or shown and refused.
  - **How it works.** A model of the board copies the game's rules for falling coins, departing bags and
    closing gaps, quirks included. The search tries beams of the best positions first, then every
    position, and proves "can no longer be won" only when no clicks win in any order the bags could
    leave in. It looks at 300 positions per board tick, so the same board gets the same answer at the
    same tick everywhere. Replays record H and U (new events) and play hints, undos, prices, refused
    clicks and early game overs back the same.
  - **Scores.** The mod says it affects scores, so its games keep their own high-score tables, and the
    mods sign shows.
  - **Tested** (bot games under rundesk; `-autoplaysolver[=N]` makes the bot click the solver's plan N% of
    the time, `-autoplayhints` press H first):
    - Following the plans, the bot played to level 200 at Easy and 180 at Hard without losing a level.
    - No level the solver called lost was ever won (the game logs "solver: WRONG" if one is).
    - Nine games with H presses, prices and "end the game when lost" each replayed exactly ("replay:
      verified").
    - An answer took a median of about 9,000 positions at Easy and 33,000 at Hard (0.3 s and 1.1 s of
      play); at Hard about one search in 20 reached the limit.
    - Undo and free hints (`-autoplayundo[=N]` presses U in N% of the bot's turns): 45 undos, at rest
      and mid-fall. After each, the board was the one clicked (the game logs "solver: WRONG" if not).
    - Warnings (`-autoplaycheck` moves the mouse to a group and waits for its check before clicking):
      about 1,600 checked clicks in 36 games. All 27 clicks on groups found to lose left a lost level;
      no click found to win did. A check took a median of 1,800 positions (6 ticks).
    - Refused clicks: 78 refusals in two games with "Show and refuse".
    - All 12 replays of these games verified, with their undos, free hints and refused clicks.
    - The web build compiles it; it has not been played in a browser yet.
- **Winnable Puzzle boards** (the `winnable-puzzles` mod, `features.winnablePuzzles`;
  `src/PuzzleBuilder.h`). Puzzle mode only: every board can be won.
  - **Why the original's can't always be.** It builds a board backwards, pushing small groups of one
    colour into the columns as if clicks were taken back. But a group can come out split (another coin
    ends up between its coins) or touching coins of its own colour, and then clicking the groups in the
    reverse order is not a legal win.
  - **What the mod does.** It grows its groups the same way, from the same random numbers, but keeps a
    coin only if the group stays exactly what a click on it would take: connected, and touching no other
    coin of its colour. A new column starts only next to the columns already there, one per group at
    most, so the columns empty one at a time from the outside in. (When a click emptied two columns at
    once, a bag could land in the outer one, and the game closed the gap before the bag left.) The bags
    go on as in the original.
  - **The winning line.** Clicking the groups in the reverse of the order they were built clears the
    board and drops every bag. When a board is made, the game plays that line on the solver's model
    and logs "winnable: level N: … clicking them in reverse wins" (or "WRONG"). With the Puzzle Solver
    on, that line is its first answer, so it says "can still be won" at once and its hints follow it.
  - **Scores.** The mod says it affects scores (its own high-score tables, the mods sign).
  - **Tested** (bot games under rundesk):
    - 251 boards at Easy, Normal and Hard: the reverse order won every one. (Before the one-new-column
      rule, about 4% failed.)
    - Following the solver, the bot reached levels 77, 75 and 73 (Easy, Normal, Hard) without losing a
      level, and the solver needed no search of its own on any of them.
    - Six replays (random play, with and without the solver) verified.
- **Pickpockets** (the `pickpocket` mod, `features.pickpocket`; `Board::UsePickpocket`). A powerup in every
  mode.
  - **What one does.** It lifts a group too small to click: a single coin, or two where three are needed.
    The coins go in a puff, as under a bag, for no points; combos and colour streaks don't count it. In
    Strategy it uses up a move, like a click.
  - **How.** Right-click the group. Or press P, or click the counter on the steps under Mr. Money: it
    blinks "pickpocket ready", small groups light up under the mouse, and the next click on one uses
    it. P again puts it away.
  - **How many.** Three at the start of a game, five at most, and more are earned with spare bags
    (below); a free one at each new level is a setting, off by default (version 1.0 gave one). The
    count is kept in the savegame (a "BMPK" trailer the original's reader ignores).
  - **Spare bags** (`perBag`, one by default; `Board::EarnPickpockets`). So that Pickpockets don't just
    make the game easier, they are earned with bags the level didn't need:
    - Action and Strategy: one for each bag still on the board when the level ends (the bags the
      original counts for its Excess Baggage bonus, `ClearBoardForLevelEnd`).
    - Puzzle: a won level goes on while a group can be clicked ("extra bags earn pickpockets";
      `Board::PuzzlePlaysOn`), then it is swept as before. Each bag dropped past the needed ones, on
      the winning click or after it, earns one and flies to the counter. The solver rests while the
      level plays on, and its undo is gone, as after any win.
    - "+1 pickpocket" pops up for each one earned; none past the most in hand.
    - Tested (version 2.0, bot games under rundesk; `-autoplaypocketbags` lifts the coin under a bag):
      36 games in every mode, 52 Pickpockets earned, 159 used, 85 Puzzle levels played on and every
      one of them ended; all 12 replays verified; a game saved while a won level played on resumed in
      it. The bots earned about one every five levels in Action, one every three in Strategy and one
      every two in Puzzle (where they don't aim for bags).
  - **Puzzle.** The game goes on while a Pickpocket can still lift a coin, and with no click left one is
    armed by itself. The Puzzle Solver counts no Pickpockets: on a level it can't win it says "no way
    to win without a pickpocket", "end the game when lost" waits until they are gone, and its undo
    gives back a Pickpocket it takes back.
  - **Replays.** A use is a new event (`OP_POCKET`, with where). Arming one is not recorded: it changes
    only what lights up.
  - **Scores.** The mod says it affects scores (its own high-score tables, the mods sign).
  - **Tested** (bot games under rundesk; `-autoplaypocket[=N]` lifts a small group in N% of the bot's
    turns and whenever nothing can be clicked, by P and a click or by a right click in turn):
    - 100 Pickpockets in 15 games of Action, Strategy and Puzzle (two with the solver, undo and "end
      the game when lost"); all 13 replays verified.
    - Every Puzzle game ended with none left; a level the solver called lost played on while some were.
    - An undo of a Pickpocket gave it back; a saved game resumed with the count it was saved with.
- **Board size** (the `small-board` mod, `features.boardSize`). Every mode: fewer columns (4 to 14) and
  rows (6 to 15), 10 x 12 by default.
  - **Smaller only.** The 29-pixel coins already fill the vault (14 x 15), so a bigger board would need
    smaller coins and new art.
  - **How.** The game's rules already loop over its own column and row counts; the board uses the top-left
    part of the 14 x 15 grid and is drawn centred on the same floor, with the rest of the vault dimmed.
    The Puzzle generator uses the board's columns and floor where the original has 14 and 15, fills each
    column to 3/5 of its height (row 6 of 15) and keeps two empty rows on top. Action and Strategy start
    with 6 rows of 15 in proportion.
  - **Puzzle.** A level needs no more bags than the board has columns for (one fewer). The solver keeps
    its 14 x 15 model with the board on its floor (the empty columns past the side change nothing:
    gaps close only between coins). Winnable Puzzles builds to the board's size.
  - **Savegames** keep the original's layout: a blank next coin is written past the board's columns.
  - **Scores.** The mod says it affects scores (its own high-score tables, the mods sign).
  - **Tested** (bot games under rundesk, 10 x 12, 4 x 6, 6 x 15 and 14 x 8, every mode):
    - With Winnable Puzzles and the solver, the bot reached level 101 on 10 x 12 (Hard) and 224 on 4 x 6
      without losing one; every board's reverse build order won (383 boards, with 56 at 14 x 8).
    - The solver on the original generator at 6 x 15: no wrong answer.
    - 20 replays verified; a saved game on a small board resumed.
- **More coin colours** (the `more-colours` mod; the tunables `coins.colors` and `coins.puzzleColors` now go
  up to 16). Eleven colours after the game's five: orange, cyan, silver, purple, brown, pink, charcoal,
  lime, teal, navy and maroon, in that order. Six in every mode by default, with a setting for Action and
  Strategy and one for Puzzle (2 to 16). Many colours make Diagonal Groups' Puzzle hard again.
  - **The coins** are made when the game starts, from the game's coins or a mod's (HD too): each new colour
    takes another colour's coins with their brightness and its own hue, so the shine stays white. Each
    keeps that colour's sign, chosen so colours that look alike have different ones (navy the cent, blue
    the pound; maroon the cent, red the dollar; charcoal the dollar, silver the yen).
    The highlighted coins, both flip-frame sets, the selection glow and the dollar bomb's tint have them.
  - **Rules** are the game's: as with five colours, the first level on Easy has one fewer.
  - **Puzzle.** The solver and Winnable Puzzles take up to 16 colours (the solver's bag marker moved from 8
    to 16). The solver's position hashes for the game's five colours are unchanged; only equal hashes
    count, so the others changing changed no answer.
  - **Scores.** A mod with tunables affects scores (its own high-score tables, the mods sign).
  - **Tested** (bot games under rundesk, 6 to 16 colours, every mode, with and without Diagonal Groups):
    - With Winnable Puzzles and the solver the bot won every level to 74 on Hard with 8 colours, and to 75
      (Hard) and 79 (Easy) with 16 and diagonal groups.
    - The solver gave no wrong answer with 7, 12 and 16 colours on the original generator.
    - With 16 colours and diagonal groups the bot's Easy Puzzle games ended at levels 6 to 8 (17 to 30
      with the game's colours).
    - 37 replays verified; replays recorded before the 16-colour change still verify.
- **Diagonal groups** (the `diagonal-groups` mod, `features.diagonalGroups`). Every mode: coins of a colour
  that touch at a corner are one group, so groups are bigger and easier to find.
  - **How.** The game's group flood (Board::FloodFill) also goes across corners: the hover, the click, the
    group sizes for "no moves left" and the hints. The flood Compact uses to close gaps does not (it
    measures the pile, not a colour).
  - **Puzzle.** The solver's groups follow the rule. Winnable Puzzles keeps a built group only if nothing
    of its colour touches it at a corner either. The original generator is unchanged, so its boards get
    easier.
  - **Pickpockets** lift groups by the same rule.
  - **Scores.** The mod says it affects scores (its own high-score tables, the mods sign).
  - **Tested** (bot games under rundesk, every mode, alone and with More Colours, Pickpocket, Small Board
    and the Puzzle Solver together):
    - With Winnable Puzzles and the solver the bot reached levels 73 (Hard) and 77 (Easy) without losing
      one; the solver gave no wrong answer on the original generator or with the other mods.
