# Big Money's framework: SexyAppFramework 1.2 slot and field reference

Big Money Deluxe (game PE linked 2005-11-14, VS.NET 2002) is built on SexyAppFramework 1.2, the
same tree as the public [sandboxmo-de/SexyAppFramework-v1.2](https://github.com/sandboxmo-de/SexyAppFramework-v1.2)
(reference copy: `E:\retools\refs\saf12`, not in this repo). The tables below are generated from those
headers by `tools/saf_vtable_layout.py` (vtable slots) and `tools/saf_struct_layout.py` (field offsets),
with the build differences below applied, and checked against the binary:

- every framework class's primary vtable has exactly the computed slot count (51 classes);
- anchor offsets verified in the disassembly: SexyAppBase `mWidgetManager` 0x2e4, `mDDInterface` 0x330,
  `mMusicInterface` 0x338, `mCursorImages` 0x378, `mCustomCursorsEnabled` 0x4c8, `mDemoCmdOrder` 0x548,
  `mSyncRefreshRate` 0x574, `mVSyncUpdates` 0x578, `mWaitForVSync` 0x588, the property maps
  0x598/0x5a4/0x5b0/0x5c8, `mResourceManager` 0x5d4; SexyApp `mDontUpdate` 0x645, `mRegCode` 0x6a0,
  `mIsRegistered` 0x6bc, `mTimesPlayed` 0x6c0, `mTimesExecuted` 0x6c4; Widget `mX` 0x2c, `mY` 0x30,
  `mVisible` 0x4c, sizeof 0x80 (secondary ButtonListener vtables at +0x80); sizeof(Dialog) 0x148.

**Build differences from the public 1.2 headers** (the binary is a slightly earlier snapshot):

| Header says | Binary has | Evidence |
|---|---|---|
| `virtual bool SexyAppBase::ProcessDeferredMessages(bool)` | non-virtual (no slot) | slot 7 is `Process` (1,412 bytes, the update/draw loop) |
| `virtual void SexyAppBase::CursorThreadProc()` | non-virtual (no slot) | `~SexyAppBase` sits at slot 17 |
| `std::string mDemoCommentStr; ulong mDemoCommentDec;` | absent | `mDemoBuffer` directly follows `mDemoFileName` (0x510) in the ctor |
| `int mDemoPlayFrame;` | absent | ctor stores 0x530..0x54c match the header order without it |
| `float mMouseSensitivity;` | absent | `mStringProperties` at 0x598 |

So sizeof(SexyAppBase) = 0x5e0 (0x5dc of members, 8-aligned), sizeof(SexyApp) = 0x6d0, and WinBMApp's
own members start at +0x6d0.

**Container sizes** (VC7 Dinkumware): `std::string` 28 bytes (allocator, 16-byte buffer at +4, size
+0x14, capacity +0x18; heap pointer at +4 when capacity > 15), `std::list`/`map`/`set` 12 (allocator,
head +4, size +8), `std::vector` 16 (allocator, first +4, last +8, end +0xc).

**Reading virtual calls in the decompilation**: `(**(code **)(*this + 0xNN))()` is slot NN/4 of the
object's primary vtable. Widget-derived game classes have a second vtable (ButtonListener etc.) at +0x80
(+0x148 after a Dialog's ButtonListener for EditListener/CheckboxListener/SliderListener members of
dialogs, see the RTTI vtable offsets in the inventory).
