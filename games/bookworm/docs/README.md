# BookWorm Deluxe port

BookWorm Deluxe (PopCap Games, 2004) is decompiled and ported the same way as Bejeweled Deluxe and Big
Money Deluxe: the original's game classes are translated function by function onto the portable
SexyAppFramework (`framework/`, SDL2 + Emscripten), and the game data is copied from the user's own install.
Nothing from the game itself is in the repository: not its images, sounds, music or fonts, and not its word
list, bonus words or definitions either.

## The binary

- The retail install (`C:\Program Files\PopCap Games\BookWorm Deluxe`, version 1.03, a "CD-protect"
  edition) has one executable, `Bookworm.exe`. It is PopCap's CDProtect launcher (106,496 bytes) with the
  unencrypted game PE appended after the `!popcapcdprotect!` marker: 1,318,912 bytes at file offset 0x1a011.
  The launcher checks a hardware fingerprint or the CD, then runs a copy of exactly those bytes.
- The game PE was linked 2004-04-15 with Visual Studio .NET 2002 (MSVC 7.0, no LTCG). It has full RTTI (159
  classes, 187 vtables). The game code is 0x401000-0x437800: 852 functions in about 33 source files linked in
  alphabetical order.
- The framework is an internal SexyAppFramework from early 2004, older than any public release (see
  FRAMEWORK_2004.md); the libraries are ImageLib (libpng, libjpeg, zlib), BASS 2.0 for the MO3 music and
  DirectSound for sounds.

## Reproducing the analysis

Ghidra 12.1.4 + JDK 21 (`E:\retools`), Python 3, and Big Money's analysed binary for the carried-over names
(its worktree, `claude/bigmoney-1912c8`). Long runs go under `build/native/rundesk.exe` (hidden, low priority).

```bash
python tools/extract_game_exe.py "C:/Program Files/PopCap Games/BookWorm Deluxe/Bookworm.exe" -o re/bookworm/bin/BookwormGame.exe
python tools/rtti_msvc70.py re/bookworm/bin/BookwormGame.exe re/bookworm/rtti
MSVC70=1 SYMBOLS=re/bookworm/rtti.jsonl build/native/rundesk.exe bash tools/ghidra_import.sh re/bookworm/bin/BookwormGame.exe bookworm_game re/bookworm/gh
python tools/rtti_msvc70.py re/bookworm/bin/BookwormGame.exe re/bookworm/rtti --functions re/bookworm/gh/functions.jsonl
GHIDRA_PROJECT=bookworm_game GHIDRA_PROGRAM=BookwormGame.exe EXPORT_DIR="$(pwd -W)/re/bookworm/gh" build/native/rundesk.exe bash tools/ghidra_headless.sh apply games/bookworm/docs/symbols/*.jsonl
python games/bookworm/tools/bookworm_inventory.py
```

`re/` is git-ignored: the carved exe and Ghidra's export contain the game's code and strings.
`games/bookworm/docs/symbols/05_bigmoney_match.jsonl` came from `tools/funcmatch.py` against Big Money's
export (see FRAMEWORK_2004.md section 1); the other symbol files from the analysis.

How the analysis was done: an RTTI scan named the classes and vtables; byte matching against Big Money
named about 700 framework, STL and CRT functions; three framework analyses mapped the 2004 framework
(FRAMEWORK_2004.md); seven module analyses wrote the parts of GAME_NOTES.md, each naming its functions for
Ghidra; a reconciliation pass settled the names that cross module boundaries (GAME_NOTES.md Part 8). Nothing
was learned by running the original: it is behind DRM, and its BASS music cannot be silenced.

## Building and running

```bash
python games/bookworm/tools/stage_bookworm_assets.py   # copies the game's files to assets/bookworm/
tools/build.sh native                                  # build/native/bookworm.exe (and the other games)
tools/build.sh web                                     # build/web/bookworm.html/.js/.wasm
```

- **Native.** `bookworm.exe` finds `assets/bookworm/` next to itself (or up to two levels up), or the retail
  install. `-gamedir=` overrides that. Saves go to `%APPDATA%\wasm-bejeweled\BookWorm Deluxe\`: the players'
  saved games (`players/<name>/classic.dat`, `action.dat`; with mods that change play, see Mods) and `registry.ini` for the original's
  `HKLM\SOFTWARE\PopCap\BookWorm` values (player profiles, high scores, options).
- **Web.** `bookworm.html` (`games/bookworm/web/shell.html`) imports the player's game folder (or a .zip of
  it) into its own IndexedDB-backed folder `/bwpersist`, separate from the other games'. It saves the same
  way as Bejeweled's shell: IDBFS syncs, a localStorage backup of the user files, and one running copy per
  browser.
- **Music** is the original MO3 module played by order position through libopenmpt
  (`platform/openmpt`), like BASS did.
- Test runs follow `CLAUDE.md`: native runs only under `build/native/rundesk.exe`, and web pages only with
  `?silent=1`. `games/bookworm/tools/mo3info` prints the MO3's orders without an audio device.

## Mods

The mods are in `games/bookworm/mods/`, one folder each, with the shared mod system (docs/MOD_MENU.md): natively
copy a folder into `build/native/mods-bookworm/` (or pass `-modsdir=`), on the web give the Mods panel the folder
or a .zip of it; F2 opens the mod menu in the game. A mod that changes play (`"affectsScores": true`) gives the
games played with it their own high scores (registry `Scores-<key>` instead of `Scores`) and saved games
(`players/<name>/classic-<key>.dat`), the key being the mod set's score key, so they never mix with the
original's.

| Mod | What it does |
|---|---|
| `solver` (Word Solver) | A HINT button beside SUBMIT, and Tab: selects a word on the board, scored exactly as Submit would. First the word that takes the lowest fire tile (while there are fire tiles), then the bonus word, the 10 best-scoring words and the longest; each press gives the next. A tag beside the word says which it is and warns when a word ends the game (a bottom-row fire tile left out, in Classic) or drops a fire tile to the bottom row. Settings: fire first, how many best words, the tag, and save bonus tiles: every hint keeps the green, gold, sapphire and diamond tiles on the board where a path as safe goes without them (the fire hint once it takes the lowest fire tile), so they stack up; a CASH IN hint after the best words is the best word that uses them (each adds to the multiplier of the whole word). |
| `undo` (Undo) | An UNDO button beside OPTIONS, and Ctrl+Z: takes back the last word or scramble (up to 10, setting 1..100), within a level and while in play. The board, score, fire meter, Lex and bonus word come back as they were, and the same word played again brings the same new tiles (the generators come back too). The clocks run on. |
| `collins` (Collins Scrabble Words) | Adds Collins Scrabble Words (CSW24, 280,652 playable words; the game has 151,381) to the dictionary, with their definitions in Lex's balloon, in the game's style; a word without one gets the note "A word from Collins Scrabble Words." A click on a definition balloon opens the word on collinsdictionary.com (setting: Wiktionary, or nothing). The list is the player's own and git-ignored: `python games/bookworm/tools/make_collins_mod.py <NASPA Zyzzyva folder> [--definitions <words with definitions.txt>]` writes `collins-words.txt` and `collins-defs.txt` into the mod folder. Start-up takes about 1.4 s longer natively. |
| `rude-words` (Rude Words) | Adds 312 swear words, crude slang and internet slang the game's list leaves out (no slurs), from our own list. Each one played sets fire to some of the tiles that drop in to replace it, never on the bottom row: 2 (0..9), one per so many letters, or all of them. Settings for its points (a multiplier, 0 or negative too) and bonus tiles (as usual, none, or a rude word removes them all). Lex comments in his balloon (65 comments, the definition under it) and cries danger; the level and game-over page counts the game's rude words and the player's all-time total. The solver ranks such words after the safe ones ("SETS FIRE"). |
| `type-word` (Type a Word) | Type a word to select it on the board, and press Enter to play it (Enter plays a clicked selection or a hint too). Each letter selects the best path for the letters so far, so the selection can move as the word grows; a letter the board cannot add is refused with a buzz. Of the paths that spell the word: one that does not end the game, then the most fire tiles, the fewest fire tiles dropped, none dropped to the bottom row, the best score (MOD_IDEAS.md 4.6). Backspace takes back a letter, Esc clears; Q types the Qu tile. Space, Tab and Ctrl+Z keep their jobs. The usual high scores: every typed word could be clicked. |
| `greedy-bots` (Greedy Bots) | In Classic, two simple players play their own games from the board you began with, while you play: one always plays the best-scoring word, the other the word that takes the most urgent fire first (else the best). On the game-over page a balloon above Lex gives their scores, how far each got and which of them you beat. A model of the Classic rules plays them, checked against the game move by move; a saved game keeps them. Your own game is unchanged, with the usual high scores. |
| `missed-words` (Missed Words) | After each word that was not the board's best, Lex's balloon gives the best-scoring word the board had; the level and game-over pages give the points missed. The note can name a word still on the board, so its games keep their own high scores. Saved with the game: an undo takes a word's note back. |
| `par` (Par) | Each board's par is the points of its best word. After each word Lex gives its points as a percentage of par; the level and game-over pages give the level's and the game's percentage. Play is unchanged (usual high scores). |
| `colour-blind` (Colour-Blind Mode) | A symbol in the top-left corner of each special tile, so they differ by shape too: a circle on green, a square on gold, a rhombus on sapphire, a star on diamond, a triangle on fire. Drawn as shapes, sharp at any render scale; the setting "large" draws them bigger on a dark plate. |
| `daily-board` (Daily Board) | One board a day per mode, the same for everyone: each day's games start from the same tiles and first bonus word, seeded by the date. Lex names the day at the start; results go into `daily-board.txt` in the player's folder, and the game-over page's balloon gives this game, the best of the day, the best day and the days played. The day and the generators are saved, so a continued game counts for its own day. Its own high scores. |
| `word-journal` (Word Journal) | Every word played goes into `word-journal.txt` in the player's folder (an undone word is taken back). At game over a WORD JOURNAL button opens the journal: words, games and points so far, the best and longest words, the average, a heatmap of the letters played against how often each is dealt, and the best word of each level (a click on that page turns it). |
| `select-definitions` (Definitions While Selecting) | Lex gives a word's definition as soon as the selection spells it, not only once it is played, and changes it as the selection does; a word with no definition shows none. With `collins`, most words have one. Needs definitions on in the options. |
| `widescreen` (Widescreen) | A 16:9 screen (854 x 480): every screen of the game as usual on the left, and beside the board a panel in a frame cut from the board's backdrop. It lists the words played this game, newest first, by level, each in the colour of its best special tile, with its points (and a bonus word's). They are read from the board's game log, so an undo or a continued game shows them as they stand. With `solver` on, the solver's list for the board comes first, its kind and points beside each word; a click on one selects it, as its hint would. The web page takes the screen's shape. Play is unchanged (usual high scores). |
| `livesplit` (LiveSplit) | Windows: the game keeps a small block of its state in memory (mode, level, score, game over and why, the board's serial; `src/LiveSplitBlock.h`, the same layout as Big Money's, game id `BWDX`) for the autosplitter `BookWormDeluxe-byopop.asl` (in the mod, and `tools/livesplit/`). It starts when a new game begins (never a continued one), splits at each level cleared or at score marks such as 25K, and resets when the game ends or is left. Split templates ("Classic - 10 Levels", "Action - 100K Points", ...) are copied to `<user folder>/livesplit` on first use; categories with Classic or Action in the name start only in that mode. Play is unchanged. |
| `hd4x-textures` (4x Textures, generated) | Every image and font strip at 4x, upscaled with Real-ESRGAN from the player's own game files: `python games/bookworm/tools/make_hd4x_mod.py [--game <BookWorm folder>] [--upscaler <realesrgan-ncnn-vulkan.exe>]` writes it into `games/bookworm/mods/hd4x-textures/`. It is made from the game's art: git-ignored (`mods/.gitignore`), never commit or share it. |

The tests use the `-autoplay` bot. With `-autoplayhints=1` it plays the solver's first hint every move (Tab,
then Submit) and logs `HINT MISMATCH` wherever the game scores a word otherwise than the solver said; on seed 1
it plays Classic to level 24 in 30,000 updates (193 words, fire, bonus and best hints) with no mismatch.
With the solver's `saveBonus` on, it logs `SAVE MISMATCH` for a hint that spends bonus tiles where a path as safe
goes without them (MOD_IDEAS.md 4.8). With
`-autoplayundo=1` as well it undoes every other word (the button and Ctrl+Z in turn), checks the board against
the one before the word, plays the same hint again and checks the board against the first play's (Classic
only: in Action the timed fire tiles depend on when the word comes); `UNDO MISMATCH` where one differs. Seed
1, 30,000 updates: Classic 109 checks, Action 56, no mismatch. With `-autoplaymodel=1` (Classic, without
undo) the greedy bots' model takes every move the game takes, from the game's first board, and must come to
the same board, score, fire meter, bonus word and level at each rest, and to the same end; `MODEL MISMATCH`
where it does not (MOD_IDEAS.md 4.2). With the mod `greedy-bots` the game-over note gives the bots' results,
and `-autoplayshots` also shoots the game-over page with their balloon. `-autoplaycontinue=1` answers the
continue-game question yes, so a second run in the same user dir goes on with the game the first one's quit
saved. With `-autoplaytype=1` (the mod `type-word` on) the bot types its words, mostly in lower case, and
presses Enter; now and then it takes a letter back with Backspace or clears with Esc and types again. Before
each key the selection must spell the letters typed so far, and before Enter it must be the best of the word's
paths as the solver finds them; `TYPE MISMATCH` where not. Hints and Submit-button words go by Enter half the
time. Seeds 1 to 6, Classic and Action: 297 typed words (79 with more than one path, 3 with the Qu tile),
1,931 checks, no mismatch; 143 hints sent with Enter. `-dailydate=<yyyymmdd>` makes the mod `daily-board`
deal that day's board instead of today's. `-autoplayshots` also shoots the game-over page with the mods'
balloon (`greedy-bots`, `daily-board`), the word journal (`word-journal`: the bot opens it, shoots it and
closes it) and the first definition shown for a selection (`select-definitions`: the bot waits for it).

LiveSplit's tests (`games/bookworm/tools/livesplit/run_tests.sh <out dir>`, about 4 minutes, under rundesk) check
the block's offsets against the .asl, compile the .asl with the .NET Framework compiler (`asltest`), read the block
from a running game with `lsprobe.py` (no torn reads, every write the game's), and run 29 scenarios through the
real script (`lsdecide.py`: level and score splits, the mode guard, leaving and continuing a game, a modded game,
the mod off). `-livesplitlog=<file>` logs each write of the block. LiveSplit itself is not part of the tests.

```bash
mkdir -p <dir>/mods && cp -r games/bookworm/mods/solver games/bookworm/mods/undo <dir>/mods/
timeout 600 build/native/rundesk.exe <full path of build/native/bookworm.exe> -userdir=<dir>/user -modsdir=<dir>/mods -fast -seed=1 -autoplay=1 -autoplaymode=classic -autoplayhints=1 -autoplayundo=1 -autoplaycap=30000 -autoplaylog=<dir>/log.txt
```

## Status (2026-10-19)

- **Analysis** (milestone 1): complete. GAME_NOTES.md specifies every game function; all 852 game functions
  are named in Ghidra; the 2004 framework map is docs/FRAMEWORK_2004.md.
- **Native port** (milestone 2): every ported game class is translated (`games/bookworm/src`, about 14,000
  lines); it builds without warnings. Checked in hidden scripted runs under rundesk:
  - the title screen (texts read from Bookworm.exe), the new-user dialog, the game selector with Lex's
    balloon, the help screen and its topics, the options dialog, the player list;
  - Classic and Action played by the `-autoplay` test bot (`src/testhooks`) through level-ups, game over and
    the Hall of Fame (Classic: level 8, 58,970 points; Action: level 14, 152,360); the level-up, game-over and
    Hall of Fame screens; fire, green, gold and gem tiles, bonus words, hints, scrambles;
  - leaving a game and continuing it in a new run (`players/<name>/classic.dat`): the board comes back;
  - the same `-seed` and script (or `-autoplay` seed) give byte-identical screenshots every run, and the
    bot's log replays as a plain `-script`.
- **Web build** (milestone 3): `bookworm.html` checked in the Browser pane with `?silent=1`: importing the
  game folder (as a .zip, including Bookworm.exe), the title, a new player, Classic play, leaving the game,
  and a page reload that keeps the player and offers the saved game, which continues with its board and
  score; no console errors.
- **Not compared with the original**: the original exe is not run (DRM, BASS sound), so fidelity rests on the
  analysis. The music is checked at the decoder level (`tools/mo3info`: every section order plays); hidden
  test runs are silent, so loudness and fades have not been listened to.

How to test:

```bash
games/bookworm/tools/run_script.sh <script.txt> <user dir> [seconds] -seed=1
timeout 900 build/native/rundesk.exe build/native/bookworm.exe -userdir=<dir> -fast -seed=1 -autoplay=1 -autoplaymode=classic -autoplaylog=<file> -autoplayshots=<prefix>
```
