# BookWorm Deluxe port

BookWorm Deluxe (PopCap Games, 2004) is decompiled and ported the same way as Bejeweled Deluxe and Big
Money Deluxe: the original's game classes are translated function by function onto the portable
SexyAppFramework (`framework/`, SDL2 + Emscripten), and the game data is copied from the user's own install.
Nothing from the game itself is in the repository: not its images, sounds, music or fonts, and not its word
list, bonus words or definitions either.

## The binary

- The retail install (`C:\Program Files\PopCap Games\BookWorm Deluxe`, version 1.03, a "CD-protect"
  edition) has one executable, `Bookworm.exe`. It is PopCap's CDProtect launcher (106,496 bytes) with the
  unencrypted game PE appended after the `!popcapcdprotect!` marker: 1,318,912 bytes at file offset 0x1a011.
  The launcher checks a hardware fingerprint or the CD, then runs a copy of exactly those bytes.
- The game PE was linked 2004-04-15 with Visual Studio .NET 2002 (MSVC 7.0, no LTCG). It has full RTTI (159
  classes, 187 vtables). The game code is 0x401000-0x437800: 852 functions in about 33 source files linked in
  alphabetical order.
- The framework is an internal SexyAppFramework from early 2004, older than any public release (see
  FRAMEWORK_2004.md); the libraries are ImageLib (libpng, libjpeg, zlib), BASS 2.0 for the MO3 music and
  DirectSound for sounds.

## Reproducing the analysis

Ghidra 12.1.4 + JDK 21 (`E:\retools`), Python 3, and Big Money's analysed binary for the carried-over names
(its worktree, `claude/bigmoney-1912c8`). Long runs go under `build/native/rundesk.exe` (hidden, low priority).

```bash
python tools/extract_game_exe.py "C:/Program Files/PopCap Games/BookWorm Deluxe/Bookworm.exe" -o re/bookworm/bin/BookwormGame.exe
python tools/rtti_msvc70.py re/bookworm/bin/BookwormGame.exe re/bookworm/rtti
MSVC70=1 SYMBOLS=re/bookworm/rtti.jsonl build/native/rundesk.exe bash tools/ghidra_import.sh re/bookworm/bin/BookwormGame.exe bookworm_game re/bookworm/gh
python tools/rtti_msvc70.py re/bookworm/bin/BookwormGame.exe re/bookworm/rtti --functions re/bookworm/gh/functions.jsonl
GHIDRA_PROJECT=bookworm_game GHIDRA_PROGRAM=BookwormGame.exe EXPORT_DIR="$(pwd -W)/re/bookworm/gh" build/native/rundesk.exe bash tools/ghidra_headless.sh apply games/bookworm/docs/symbols/*.jsonl
python games/bookworm/tools/bookworm_inventory.py
```

`re/` is git-ignored: the carved exe and Ghidra's export contain the game's code and strings.
`games/bookworm/docs/symbols/05_bigmoney_match.jsonl` came from `tools/funcmatch.py` against Big Money's
export (see FRAMEWORK_2004.md section 1); the other symbol files from the analysis.

How the analysis was done: an RTTI scan named the classes and vtables; byte matching against Big Money
named about 700 framework, STL and CRT functions; three framework analyses mapped the 2004 framework
(FRAMEWORK_2004.md); seven module analyses wrote the parts of GAME_NOTES.md, each naming its functions for
Ghidra; a reconciliation pass settled the names that cross module boundaries (GAME_NOTES.md Part 8). Nothing
was learned by running the original: it is behind DRM, and its BASS music cannot be silenced.

## Building and running

```bash
python games/bookworm/tools/stage_bookworm_assets.py   # copies the game's files to assets/bookworm/
tools/build.sh native                                  # build/native/bookworm.exe (and the other games)
tools/build.sh web                                     # build/web/bookworm.html/.js/.wasm
```

- **Native.** `bookworm.exe` finds `assets/bookworm/` next to itself (or up to two levels up), or the retail
  install. `-gamedir=` overrides that. Saves go to `%APPDATA%\wasm-bejeweled\BookWorm Deluxe\`: the players'
  saved games (`players/<name>/classic.dat`, `action.dat`) and `registry.ini` for the original's
  `HKLM\SOFTWARE\PopCap\BookWorm` values (player profiles, high scores, options).
- **Web.** `bookworm.html` (`games/bookworm/web/shell.html`) imports the player's game folder (or a .zip of
  it) into its own IndexedDB-backed folder `/bwpersist`, separate from the other games'. It saves the same
  way as Bejeweled's shell: IDBFS syncs, a localStorage backup of the user files, and one running copy per
  browser.
- **Music** is the original MO3 module played by order position through libopenmpt
  (`platform/openmpt`), like BASS did.
- Test runs follow `CLAUDE.md`: native runs only under `build/native/rundesk.exe`, and web pages only with
  `?silent=1`. `games/bookworm/tools/mo3info` prints the MO3's orders without an audio device.
