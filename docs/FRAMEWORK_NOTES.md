DIFFERENCES / CLARIFICATIONS:
(a) There is no ShowFPS virtual; the vtable ends at AppCanRestore, the same as pcf.
(b) DialogButtonPress/Depress having no primary slots is standard MSVC layout for overrides of a secondary base's virtuals, not a framework difference. They map ID_YES=1000 to ButtonPress/ButtonDepress(2000+dialogId) and ID_NO=1001 to 3000+dialogId; the game handles all results in ButtonDepress.
(c) Ghidra's vfunction names inside bodies can be wrong. Examples: DoUpdateFrames calls [vt+0x40] (slot 16); SexyApp slots 101/102 are mislabeled 'WinDMApp::scalar_deleting_destructor'; 0x4662a0 is mislabeled '~WinDMApp'.
(d) The 'vfunctionN_for_ButtonListener' names on SexyApp are primary-vtable slots.
(e) LTCG custom calling conventions occur in framework internals:
  - InternetManager::GetUpdateURL: this in EAX, return buffer in ESI.
  - BetaSupport::Validate (0x46e5d0): this in EDI.
  - DoExit (0x446570): uses EDI.
  - Is3DAccelerated (0x44ff30): this in EAX.
  - MTRand::NextNoAssert: 'this' constant-folded to gMTRand.

RANDOMNESS (for gem-generation fidelity)
Generator:
- All game randomness comes from Sexy::Rand() (0x469260), which runs MTRand::Next and then NextNoAssert (0x464720).
- It is textbook MT19937: init_genrand with multiplier 1812433253, mag01 = {0, 0x9908b0df}, standard tempering.
- Each draw returns tempered & 0x7FFFFFFF, so results are 31-bit and never negative.
- A seed of 0 becomes 4357.
- SRand and MTRand::SRand take the seed in EAX (LTCG register convention).

Seeding:
1. The static initializer seeds 4357.
2. SexyAppBase::Init (vfunction50, 0x44e4d0) does mRandSeed(app+8) = GetTickCount(); SRand(mRandSeed); then srand(GetTickCount()).
3. Demo playback (0x440853) checks the magic 0x42BEEF78, freads the version and then mRandSeed, and calls SRand.
4. Nothing in the game region seeds the generator.

CRT rand (0x4dd837):
- MSVC LCG on the per-thread _holdrand at _ptd+0x14: x = x*214013 + 2531011; returns (x>>16) & 0x7fff.
- It is used only by framework temp-file naming (rand()%10000).

Signed modulo: `and eax,0x80000007; jns; dec; or; inc` is only the signed-% fix-up. Because Rand() is never negative, Rand()%2^k equals Rand() & (2^k - 1).

The 11 game draw sites (all verified):

FillBoard, FUN_004cb182:
- Callers: Board ctor 0x4cb860, state 8 at 0x4cb377, state 9 at 0x4cb46b.
- Setup: sets +0x194=0 and +0x1e8=0, then zeroes all 64 grid pointers without deleting the pieces they point to.
- Fill order: row 7 down to 0; within each row, col 0 to 7. For each cell:
  1. p = new Piece(0x78) (ctor 0x4c9aec).
  2. p->row(+0x1c) = row; p->col(+0x18) = col.
  3. p->x(+8) = double(col*51 + 203).
  4. base = (row < 7) ? (int)grid[row+1][col]->y : 0.
  5. p->y(+0x10) = double(base - Rand()%240 - 65). This is draw 1 (0x4cb225).
  6. grid[row][col] = p.
  7. do { p->color(+0) = Rand()%7; } while (HasMatch()). These are draws 2..n (0x4cb245).
- HasMatch (0x4c9cf5) scans rows, then columns, for 3 equal colors in a row. An empty cell sets the remembered color to -1, which effectively resets the run.

Cascade refill, FUN_004ca9ed (board state 4):
- Dying pieces (flag +0x4c): on ticks where tick(+0x28)%3==0, frame(+0x50)++. At 6 the piece is deleted, and +0x1a4 is cleared if it pointed to that piece. Refill waits until a tick on which no dying piece was seen.
- Refill passes, repeated until a pass spawns nothing. Each pass handles col 0..7 in turn:
  1. minY = 16 (rowY(0)), reset for every column.
  2. Scan rows 7 down to 0. For each piece with y < minY, set minY = (int)y. The cast truncates toward zero, and y can be negative.
  3. Below the first gap nothing moves. Once a gap is found, every piece above it gets row++ and velocity(+0x28)=1.0 and moves into grid[row+1]; the vacated cells are cleared.
  4. If the column had a gap, spawn a piece at row 0: x = col*51+203, y = minY - 69, velocity = 0.3 (0x506590), color = Rand()%7 (0x4cab3d).
- The refill never re-rolls matches, so new cascades can occur.
- RNG cost: one draw per gapped column per pass.
- Afterwards: vfunc+0x44, +0x194 = 0, +0x204++.

FLOATING POINT
Float-to-int:
- Every (int)double cast in game code (66 sites) calls _ftol2_sse (0x4d99c0), which truncates toward zero.
- SSE2 path: fstp qword, then cvttsd2si into EAX only. An out-of-range value gives 0x80000000.
- x87 fallback _ftol2 (0x4d99f6): fistp plus a fix-up, producing a 64-bit result.
- Ghidra drops the ST0 operand, so calls such as FUN_004d99c0(...) hide the real expression; read the disassembly.

Math calls in game code:
- abs, atan2, sqrt, sin and cos are real calls with stack doubles (17, 1, 1, 2 and 2 sites).
- pow and _CIpow are not used anywhere.
- Framework code uses the intrinsic forms instead: _CIsin and _CIcos in the rotated blitters, and inline strlen.
- Inference: the game region was built with /O1, which uses the __EH_prolog3 helpers (67 of 73 calls are in the game) and omits /Oi. The framework was built with /O2.

sin and cos:
- They use the SSE2 kernels (_sin_pentium4 0x4e42d8, _cos_pentium4 0x4e4648) when __use_sse2_mathfcns is set and both MXCSR and the x87 control word mask all exceptions.
- __use_sse2_mathfcns (0x574180) is set at startup from a CPUID SSE2 check (0x4ef762), so it is on for any modern CPU.
- The dispatch checks only the exception-mask bits, not precision control.
- The x87 fallback uses fsin/fcos with CW forced to 0x27f.
- atan2 and sqrt are x87-only (dispatchers _trandisp2 and _ctrandisp2), with the same 0x27f forcing.

Game-region wrappers (0x4c9a94 atan2f, 0x4c9ab7 sqrtf, 0x4c9ad1 atan2(float,float)): each rounds its result to float, and the result is then stored in a double field.

Vortex setup (0x4ca616):
- dx = (int)(x + 24 - cx), dy = (int)(y + 24 - cy), both truncated.
- angle(+0x60) = atan2((float)dy, (float)dx).
- radius(+0x70) = sqrtf((float)((float)dx*dx + dy*dy)).
- +0x68 = 0.
- Update (0x4cba0a): x = cos(angle)*r + cx - 24; y = sin(angle)*r + cy - 24.

Other constants:
- Swap animation (0x4cda22): (int)(cos(deg*3.14159/180.0)*(int)p->+0x30 + this->+0x1d0). It multiplies by PI = 3.14159 (constant at 0x5067d8) first, then divides by 180.0. PI is 3.14159, not M_PI.
- Background wave (0x4ca47e): (int)((sin(i*0.024 + this->+0x2e8) + 1.0) * 24.0).
- Constants at 0x506560..0x5065b0: 49, 800, 24, 1, 0.024, 88.2, 0.3, 0.15, 50, 0.015, 0.18.

x87 precision control:
- CRT startup forces PC = 53-bit (_fpmath, then _setdefaultprecision 0x4e367d, then _controlfp_s).
- DirectDraw SetCooperativeLevel is called with DDSCL_NORMAL (8, at 0x40205e) or EXCLUSIVE|FULLSCREEN (0x11, at 0x402322). Neither includes DDSCL_FPUPRESERVE (0x1000) or FPUSETUP (0x200).

- This is not verified at runtime. In the default DirectDraw-only mode, PC stays 53-bit.
- Framework blitters use fldcw pairs locally for fistp rounding and restore the control word.
